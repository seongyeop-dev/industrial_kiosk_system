# 06. 프로젝트 범위

## 주요 문제와 해결

| 문제 | 원인 | 해결 방법 | 결과 |
|:---|:---|:---|:---|
| 주문번호가 중복될 가능성 | 신규 주문번호 생성 시 기존 주문 기록과의 중복 검사가 필요함 | 기존 주문번호 목록을 확인한 뒤 중복되지 않는 식별값을 생성하도록 처리 | 주문 식별값 충돌 방지 |
| 잘못된 주문 정보가 저장될 가능성 | 필수 입력값과 수량에 대한 저장 전 검증이 필요함 | 주문 생성 전에 입력값, 수량과 필수 항목을 검사 | 불완전한 주문 생성 방지 |
| 프로그램 종료 후 주문 기록 유지 필요 | 실행 중 데이터만 사용하면 종료 시 주문 정보가 사라짐 | TXT 파일 기반 주문 저장과 불러오기 기능 구현 | 재실행 후 기존 주문 복원 |
| 주문 결과가 화면에만 표시됨 | 주문 내역을 외부 파일로 확인하고 활용하기 어려움 | 영수증 PNG 생성, JSON 로그 기록과 CSV 내보내기 구현 | 주문 결과 확인과 데이터 활용 가능 |
| 반복 UI 요소 관리가 복잡함 | 유사한 주문 UI를 개별 오브젝트와 로직으로 관리 | Prefab과 Controller 기반으로 반복 UI 생성·갱신 구조 구성 | UI 관리 방식 일원화 |
| Editor와 Windows 빌드의 파일 경로 차이 | 실행 환경에 따라 저장 기준 경로가 달라질 수 있음 | Windows 실행 환경을 기준으로 저장·불러오기 경로를 처리 | Windows 독립 실행형 빌드에서 파일 기능 확인 |

## 최종 구현 범위

- 주문 생성·조회·수정·삭제
- 주문 입력값 검증과 주문번호 중복 방지
- TXT 기반 주문 저장과 복원
- 영수증 PNG 생성
- JSON 로그 기록
- CSV 주문 데이터 내보내기
- Prefab·Controller 기반 반복 UI 구성
- Windows 독립 실행형 빌드 검증 및 주요 기능 검증
